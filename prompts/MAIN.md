- React 19, TypeScript 5, Tailwind CSS 4.
- Чистый фронтенд (SPA). База данных и бэкенд НЕ требуются.
- Сборка: Vite.

2. МАТЕМАТИКА ДЕЛЕНИЯ И АДАПТИВНАЯ СЕТКА:
- При клике на миниатюру открывается экран выбора сложности (сетки разбиения).
- Сетки генерируются автоматически на основе пропорций картинки: по меньшей стороне картинка ВСЕГДА делится на N частей, где N от 5 до 11.
- По большей стороне количество частей рассчитывается автоматически так, чтобы фрагменты оставались строго квадратными. Округляй в меньшую сторону, а лишние пиксели оригинала (остаток) — аккуратно обрезай (центрируй картинку в рамках получившейся общей сетки).
Например, если картинка размером 700 по вертикали и 1000 по горизонтали, то:
-- при делении картинки на 7 квадратов по меньшей стороне - должно получиться 7x10 квадратов размером 100x100 пикселей,
-- при делении на 5 квадратов по меньшей стороне - должно получиться 5x7 квадратов размеров 140x140 пикселей (лишняя часть картинки обрезается),
-- при делении на 6 квадратов по меньшей стороне - должно получиться 6x8 квадратов размеров 116x116 пикселей (лишняя часть картинки обрезается).
- ВАЖНО (Responsive Design): Игровое поле должно быть полностью отзывчивым. Не используй фиксированные пиксели (px) для размеров сетки. Поле должно автоматически масштабироваться (например, через max-w-full h-auto), чтобы игра идеально помещалась как на FullHD мониторе, так и на экране мобильного телефона без скролла.
Но если картинка меньше размера экрана, не нужно её растягивать.

3. ТЕХНИЧЕСКАЯ РЕАЛИЗАЦИЯ КУСОЧКОВ (CSS):
- Не нарезай картинку физически. Каждый фрагмент мозаики — это <div>, где картинка установлена как background-image.
- Чтобы в каждом квадрате отображалась только нужная часть, рассчитывай сдвиг через проценты на основе исходных координат (x, y) кусочка в правильной сетке:
  * background-size всей сетки = (количество_колонок * 100%) (количество_строк * 100%).
  * background-position для кусочка = X: (x / (колонки - 1)) * 100%, Y: (y / (строки - 1)) * 100%. (Если колонка или строка одна, то 0%).
- При перемешивании блоков свойства background-image, background-size и background-position должны оставаться неизменными (привязанными к конкретному кусочку). Меняется только их текущее положение в массиве состояния игрового поля.

4. ИГРОВОЙ ПРОЦЕСС И УПРАВЛЕНИЕ:
- После выбора сложности фрагменты перемешиваются случайным образом.
- Цель игры — восстановить исходное изображение.
- Реализуй два альтернативных способа управления, работающих одновременно:
  1) Клик-клик (или Тап-тап): Клик по одному квадрату визуально выделяет его (аккуратная рамка), клик по второму — меняет их местами.
  2) Drag-and-Drop: Перетаскивание фрагмента на место другого. ВАЖНО: Используй Pointer Events (onPointerDown, onPointerMove, onPointerUp) вместо HTML5 Drag and Drop API. Это критически важно, чтобы перетаскивание без багов работало и мышкой на ПК, и пальцем (Touch) на мобильных устройствах.
- При отпускании блока (или втором клике) блоки меняются местами.
- Логика победы: Как только все фрагменты встали на свои исходные правильные позиции, под мозаикой плавно появляется сообщение "У вас получилось!" и кнопка "Начать новую игру" (возвращает на экран выбора картинок).

5. ДИЗАЙН И СТИЛИ:
- Общий стиль: Максимально воздушный, минималистичный, элегантный.
- Чистый белый фон (bg-white), много свободного пространства.
- Фрагменты мозаики разделены едва заметными тонкими линиями.
- Кнопки крупные, контрастные, с хорошими отступами, чтобы по ним было удобно тапать пальцем на смартфонах.
- В заголовке окна браузера (<title>) должно быть прописано: "Игра-мозаика".

6. ИНТЕРНАЦИОНАЛИЗАЦИЯ (i18n):
- В правом верхнем углу экрана должен быть аккуратный переключатель языка: RU / EN.
- По умолчанию язык определяется через navigator.language. Если содержит 'ru' — включается RU, иначе — EN.
- Локализовать нужно весь текст: интерфейс выбора сложности, сообщение о победе, кнопку новой игры, заголовки.
